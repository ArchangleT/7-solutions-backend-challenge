# AGENTS.md

Guidance for AI agents and contributors working in this repository.

## Project Overview

Backend Golang coding test at `https://github.com/ArchangleT/7-solutions-backend-challenge` with two parts:

1. **User Management API** (implemented): RESTful user CRUD built with Go, MongoDB, JWT (HS256), clean/hexagonal architecture, plus a bonus gRPC service.
2. **Lottery Search System** (design-only): a wildcard-matching search design for 10M+ six-digit tickets. **Do not write code for this part** — only design documents.

## Tech Stack

- Go 1.27.3, module `github.com/ArchangleT/7-solutions-backend-challenge`
- HTTP: Fiber v2 with oapi-codegen v2 generated server (`fiber-server`)
- Persistence: MongoDB via the official `go.mongodb.org/mongo-driver/v2`
- Auth: `golang-jwt/jwt/v5`, HMAC HS256, 24h TTL
- Passwords: bcrypt (`golang.org/x/crypto/bcrypt`)
- gRPC: `google.golang.org/grpc` with protoc-generated stubs
- Mocks: `go.uber.org/mock/mockgen`
- OpenAPI spec: `api/openapi.yaml`

## Architecture

Hexagonal (ports & adapters). Dependency direction is inward only:

```
cmd/api (composition root)
    │
internal/adapter/inbound  → HTTP (fiber + oapi generated), gRPC
internal/adapter/middleware
internal/application/ports + services  (use cases, depends on domain only)
internal/domain/user, domain/statusdb  (pure entities, ports, sentinel errors)
internal/adapter/outbound → mongodb, jwt, bcrypt (implement the ports)
internal/infrastructure/db → MongoDB client lifecycle
internal/mocks → generated mocks for the ports
```

Key rules:

- **Domain** (`internal/domain/`) describes entities and **ports (interfaces)**. It holds sentinel errors (`ErrNotFound`, `ErrDuplicateEmail`, `ErrInvalidCredentials`, `ErrInvalidID`) and `ValidationError{Field, Message}`. No Fiber/MongoDB imports.
- **Application** (`internal/application/`) implements use cases against the domain ports. `user.Service` is a driving-port interface; `statusdb.Service` exists solely for the background count task.
- **Adapters** translate between frameworks and the domain. Outbound adapters wrap driver errors into domain sentinel errors. Inbound adapters must never leak service internals.
- **Composition root** `cmd/api/main.go` wires everything: Mongo client → repository → service → HTTP + gRPC servers. Backend goroutine `countUsersLoop` logs the user count every 10s.
- Passwords are hashed before persistence; the password hash is never returned over the wire.
- Feature HTTP handlers (`http/user/handler.go`) depend on an app service + a small `Responder` interface so HTTP plumbing (body decode, error mapping) stays in `http/helpers`.

## Commands

| Command | Purpose |
| --- | --- |
| `make build` | Compile API into `bin/api_user_mgr` |
| `make run` | Start the server (`APP_ENV=prod` for production config) |
| `make test` | `go test ./...` with coverage; generated code excluded from the report |
| `make test-integration` | Opt-in live MongoDB test, requires `TEST_MONGO_URI` |
| `make tools` | Install oapi-codegen, mockgen, protoc plugins into `$(go env GOPATH)/bin` |
| `make codegen` | Regenerate Fiber server + models from `api/openapi.yaml` |
| `make proto` | Regenerate gRPC stubs from `api/proto/user_service.proto` (needs `protoc`) |
| `make mock` | Regenerate gomock mocks for domain repositories and app ports |
| `make docsgen` | Bundle OpenAPI spec into `docs/` (`npx @redocly/cli`) |
| `make clean` | Remove `coverage.out`, `coverage.html`, `docs/` |

After touching `.go` files run `gofmt -w <files>`; the repo is gofmt-clean and builds with `go build ./...`.

## Code Generation

- **HTTP**: edit `api/openapi.yaml`, run `make codegen` → `internal/adapter/inbound/http/server_openapi.gen.go` (checked in, tagged "DO NOT EDIT"). Register new routes through the generated `RegisterHandlers`/`ServerInterface` in `http/server.go`.
- **gRPC**: edit `api/proto/user_service.proto`, run `make proto` → `internal/adapter/inbound/grpc/userv1/`. `grpc/server.go` mirrors REST: `CreateUser` public, `GetUser` protected.
- **Mocks**: sources are `internal/domain/user/repository.go`, `internal/domain/statusdb/repository.go`, `internal/application/ports/hasher.go`, `internal/application/ports/token.go`; run `make mock`.

## Testing

- Standard `testing` package only. No external test frameworks.
- Application services use hand-written fakes (e.g. `memoryRepo` in `service_test.go`) or gomock mocks from `internal/mocks/`.
- Repository tests use `golang.org/x/...` no — use the mongo `mtest` in `*_test.go` under `internal/adapter/outbound/mongodb/`.
- Live MongoDB connectivity test is opt-in: `TestConnect_Live` with `TEST_MONGO_URI` via `make test-integration`.
- `make test` filters generated code (`/internal/mocks/`, `server_openapi.gen.go`, `*.pb.go`) from the coverage report.

## Configuration & Secrets

- `config/config.go` loads `config/config_{env}.yaml`; env defaults to `dev`.
- Secrets (Mongo URI credentials, JWT secret) come from build-time `config/secret_{env}.go` files registered via `registerSecrets`, overridable by env vars.
- `secret_prod.go` is git-ignored (see `.gitignore`); `secret_dev.go` is committed with dev-only values.
- Precedence: env vars > registered secrets > YAML > hardcoded defaults.
- Never commit real secrets. Production is meant to be driven by `MONGO_URI`/`JWT_SECRET`.

## HTTP API Surface

| Method | Path | Auth | Notes |
| --- | --- | --- | --- |
| `GET` | `/health` | none | liveness |
| `POST` | `/api/v1/auth/login` | none | returns `{token, user}` |
| `POST` | `/api/v1/users` | none | register |
| `GET` | `/api/v1/users` | Bearer | list |
| `GET` | `/api/v1/users/{id}` | Bearer | get by id |
| `PUT` | `/api/v1/users/{id}` | Bearer | partial name/email update |
| `DELETE` | `/api/v1/users/{id}` | Bearer | delete |

Error envelope: `{"error": "human readable", "fields": {"email": "is invalid"}}`. Below middleware: `http/server.go` mounts Fiber `recover` + `middleware.LoggingMiddleware`; protected routes call `middleware.Authenticate`. gRPC equivalents: `userv1.UserService` with `authorization: Bearer <jwt>` metadata for `GetUser`.
